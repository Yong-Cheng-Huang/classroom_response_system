replacePreparedActivity 接收三類內部資料：

- PreparedActivity：組數、來源文件／表／解析版本、來源快照、全部題目與欄位及原排版 JSON。外部讀取與完整範本驗證必須先由第 6 群組完成。
- ReplacementExpectation：讀取候選時的舊活動 ID／version，以及經上游確認的替換意圖。confirmed 布林值本身不是老師身分驗證，也不能代替未來確認 token 的授權與版本綁定。
- afterCommit：可選的內部通知處理器，只在實際 COMMIT 成功後呼叫。通知僅帶新舊活動 ID，不含答案、角色、憑證或學生清單。

## 保存順序與不變量

1. 先完成整份候選的基本結構、非空、組數 2～20、題號唯一及 JSON 序列化檢查。這不是 Sheets 版型解析器，不以範例題數或兩個子題作上限。
2. 拒絕在外層交易內呼叫，避免把 SAVEPOINT 成功誤當持久 COMMIT，提前發出通知。
3. 使用 SQLite IMMEDIATE 交易，重讀目前活動，核對舊場次／version，禁止 RUNNING 替換。已有活動時必須確認，首次匯入不強加替換確認。
4. 同交易撤銷舊活動仍 CONNECTED／GRACE 的學生工作階段，增加狀態版本並保存原因，清除寬限欄位；已失效者不復活、不改寫原失效原因，老師身分及所有固定 expiresAt 不變。
5. 同交易刪除舊活動，由既有外鍵清除來源、題目、組別、成員、提交、答案及該場匯出紀錄。
6. 新建隨機活動／組別／題目／欄位識別，建立全部 READY 內容，開始／結束時間皆為 null。所有欄位都成功後才 COMMIT。
7. COMMIT 後才呼叫通知處理器。若程序在此之前中斷，恢復為完整舊場；若已 COMMIT，恢復為完整新場，不出現半新半舊。

保留 Google 連結、老師工作階段、系統接收序號高水位與配置證據、最少文件輸出管理資訊及既有 UNVERIFIED 標記。不保留本機舊答案或完整匯出恢復計畫作歷史查詢。來源快照只屬新活動，用於未來核對，不變成本場提交或標準答案。

瀏覽器暱稱及草稿處理未在本模組實作。儲存邊界不操作瀏覽器暫存；後續 4.7／5.3／9.4 仍須在新活動失效通知與重連時保留學生暱稱、清除舊草稿並要求重新選組。

## 通知結果

函式回覆 committed=true、活動識別、內部失效身分清單及下列通知狀態。此內部回覆不能直接作為學生 HTTP／WebSocket 資料。

| notification | 意義 |
|---|---|
| NOT_REQUESTED | 呼叫者未提供通知處理器，沒有假裝已通知。 |
| DISPATCHED | 處理器在 COMMIT 後成功返回，僅代表本機派送邊界成功，不代表每個分頁已接收或畫面已套用。 |
| PENDING | 處理器失敗，但資料已成功提交；不得把換場誤報為回滾或再次清場。 |

沒有新增持久化通知佇列，也不承諾 PENDING 會自行重送。程序在落盤後、通知前中斷時，後續 7.3 的授權快照須恢復權威新狀態；這項完整重連整合仍未完成。不能用此派送狀態宣稱已達 1 秒／5 秒 UI 時限。

## 匯出保護及後續整合

本場存在 PREPARING／WRITING 文件操作時，儲存邊界拒絕直接清場；UNCONFIRMED 時要求先核對或經已確認的放棄流程處理，不自動將未知結果改成失敗、完成或已回滾。拒絕時原場、身分與恢復計畫完全保留。

GE14／D33 已確認的「再次確認放棄核對後仍能建立新活動」沒有取消。其意圖驗證、最少 UNVERIFIED 資訊轉存及原子清除的完整分支由 12.10 接回本交易，不能把目前未接上的守衛當成永久阻擋政策。12.11 仍負責舊回覆及未核實範圍隔離。這些未完成分支不因本模組有交易就預先勾選。

U03 既有未核實資訊完全保持，不自行解除。U01 的寬限截止附近強制中斷、U02 凍結／休眠分類也沒有在此裁定；下列 SIGKILL 測的是資料交易，不是學生寬限恢復政策。

## 測試證據

使用真 SQLite、獨立連線與實際子程序，新增 **9 項測試全部通過**：

- 成功換場後，獨立連線在通知處理器內已能讀取完整新場、已撤銷學生及已清除舊答案。
- 最後欄位透過測試庫 trigger 注入 SQL 寫入失敗，全部舊資料及身分原樣保留，不發通知。
- 最後欄位格式錯誤、循環 JSON、取消、舊場次及舊版本均不改原場。
- RUNNING、PREPARING／WRITING、UNCONFIRMED 均拒絕擅自清除，保留原資料。
- 通知處理器失敗仍回覆 committed=true／PENDING，重開資料庫保持完整新場；外層交易呼叫被拒絕。
- 首次匯入、20 組及 21 組拒絕邊界。
- 已到期身分不復活／不改原因，老師及管理資訊保持。
- 真子程序在最後欄位 SQL trigger 內阻塞後被 SIGKILL：重開只得到完整舊場。
- 真子程序在 COMMIT 後、通知處理器內被 SIGKILL：重開只得到完整新場。

子程序以同步 pipe 標記證明到達預定故障點，再由測試程序終止；不是只在成功寫完後關檔假裝崩潰。沒有進行作業系統斷電或硬碟故障測試，也不宣稱取得相關證據。
