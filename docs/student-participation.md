# 學生端操作實作與驗證

日期：2026-11-26（Asia/Taipei）。Change：`build-local-classroom-response-system`。本次範圍為第 9 群組 9.1～9.6；完成後累計 59／85，尚餘 26 項。第 10～13 群組保持未完成。

## 操作方式

使用 Node.js 24.22.3 執行 `npm run dev`，開啟 http://127.0.0.1:3000。同一個 Chrome 中另開老師及學生分頁，各分頁使用自己的身分。空活動顯示等待匯入；老師匯入後，學生輸入暱稱或按「換個名字」，在待開始時選組。暱稱可以重複，每頁以參與者識別碼標示唯一的「本人」。

待開始只顯示題號，可離組、修改暱稱再選組；開始後禁止離換組及修改暱稱，全部題目與子題同時顯示，可使用題號導覽跳至任一題。每個作答欄修剪前後空白後須有 1～200 個可見字元，完整 emoji／組合字以共用分段規則計算。題組全部欄位合法才可送出，不由來源答案判定對錯。換行與題目／答案中的 HTML 字樣都以純文字顯示。

草稿隨輸入保存於目前分頁，重整原分頁會恢復；其他組員不會取得或覆蓋草稿。任何一人成功送出後，同組此題顯示「已送出（送出者）」及本組已提交內容，清除該題草稿並停止編輯，其他題不受影響。相同暱稱的辨識仍以參與者 ID 為準，送出者顯示其提交時暱稱。

老師結束時，學生立即停止編輯並導向 `#/results`，保留本場組別與總時長。依任務 9.5／D36，本階段驗證結果路由及狀態切換；成功答案、本組三種狀態及成功題數的完整結果內容由未完成的 11.3 承接。

身分到期或換場會顯示原因、保留暱稱並清除草稿；僅新場待開始時能重新選組。有效原分頁重連不要求重新選組。關閉後還原及原生分頁副本不能接手舊身分或草稿，沿用已完成 G1 的第二憑證及交接協定。

## 保存、提交與錯誤

草稿鍵使用 `crs.draft.` 前綴，以活動、參與者、組別及題目共同分隔；版本 1 的內容包含原始輸入，可另含已固定的 `requestId` 與正規化提交答案。只使用 `sessionStorage`，沒有改成跨分頁 localStorage，也不新增資料庫草稿或同步端點。JSON 損壞、欄位不符或待確認內容與草稿不一致時不自動送出，顯示繁體中文說明。容量／權限不足時不宣稱保存成功；未能保存待確認提交就不發出 HTTP。

提交使用既有 `POST /api/activities/{activityId}/questions/{questionId}/submissions`。發送前持久保存同一 requestId 及完整內容，防止雙擊，等待結果期間停止修改；五秒未確認時保留內容，可按「重新確認提交」沿用同一請求。斷線／重整不產生新 ID。這不是額外的自動授權或延長身分期限。

伺服器欄位錯誤會解除本次待確認狀態、保留輸入並標示欄位；本組已由他人提交則重新取得權威投影。成功回覆或同步快照都可鎖定；學生不計算名次或信任前端時間。成功、結束及換場之間的裁決沿用已完成的伺服器排序、交易及唯一約束。

卸載／換身分後不接受延遲提交回覆更新 UI 或恢復草稿。離組、身分失效及換場由身分模組清除全部對應前綴；原生副本／關閉還原則在初始化判定不具原頁憑證時清除。活動結束本身不擅增「清除全部未提交草稿」政策，已提交題目清除，不能再編輯或提交，後續失效／換場仍清除全部。

## 驗證與限制

本階段新增 3 項草稿單元測試及 3 項真 Chrome 表單流程；全套數量與最終結果見 `docs/evidence/student-verification.json`。流程測試使用臨時 SQLite 與伺服器，沒有寫入正式活動或 Google Sheets。

Chrome 案例包含：空場等待及名字保存、同名本人唯一、離換組清除、READY 無題目敘述、四子題完整才可提交、可見字元與 HTML 純文字、同題分頁草稿、原頁重整、同組鎖定及他組隔離、結束與換場、儲存失敗阻止提交、未落盤斷線及重整後相同 ID 重試、欄位錯誤提示、他人先送出與換場後延遲回覆。欄位錯誤與容量失敗使用明確隔離替身；提交、結束及換場使用正式服務。固定期限及 Chrome 原生複製／關閉還原覆核沿用全套執行的 `identity.spec.ts`。
