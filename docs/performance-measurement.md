# 固定效能量測方法

第 13.3 任務使用 `tests/fixtures/benchmark.config.json`。完整程序為 `npm run probe:performance`，F1、F2、F3 各 20 輪，同一原生有視窗 Chrome 設定檔恰 2 老師及 40 學生、20 組各 2 人。每輪建立新的隔離 SQLite，保留同一 42 個分頁，以免累積已撤銷工作階段改變固定負載。準備資料不計入命令提交後同步時間，也不以合成資料取代第 13.2 的真 Google 整合。

## 固定操作

各輪執行同時入組、開始、40 筆同題競爭、其他題分批提交、背景更新、40 分頁重整、短停機 1 秒、實際停機 31 秒及結束。每題至少有一筆有效提交，F3 涵蓋單題、兩子題與四子題；每欄使用接近 200 個可見字元的多行中文字與 emoji。排名驗唯一 1～20，競爭為 20 成功／20 拒絕，沒有降低每組一次限制。

服務停機為關閉真 HTTP／WS 服務、正常記錄身分停機、關閉並重開 SQLite 及重建全部權威服務，在原埠恢復。不是強制殺掉 Node 程序；真 SIGKILL、寫入邊界與 D38 另由第 13.4 測試。停機時間照常計入活動計時，身分固定期限不變。

## 觀測點與誤差

- `T_commit`：同一 Node 監督者程序的 `performance.now()`；以同步權威方法前後包住交易 COMMIT。整段方法執行區間加入誤差，不把 HTTP 回覆時刻當成提交時刻。
- `T_apply`：依使用者確認的 D40，以 React commit hook 記錄首次正確 DOM／狀態呈現，可由授權 HTTP 完整讀模或 WS 更新。同步核對角色、成員／提交及對應 DOM；核對耗時亦保守計入誤差。WS revision、到達及對應 DOM 套用時間另外保存，未取得不得編造，收到 WS 訊息本身不是 T_apply。
- 頁面時鐘：三次往返取最小區間，以往返中點對齊 Node 單調時鐘，半個往返與時間精度保留量列入不確定度。重整產生新文件後重新校準；非預期文件更換使校準失效，不冒充有效樣本。
- `T_ready`：監督者確認同埠健康檢查與正式授權 WS 快照可用。重整批次開始前服務已可用；服務恢復批次則重新確認可用。監督用通道隨即關閉，不增加 UI 分頁。
- `T_restored`：授權 WS 快照已套用，原角色、組別、參與者、成員、提交及完整題目均正確，並在該逐頁 React commit 保存的 DOM 計時值通過對齊核對的保守觀測上界；兩者皆恢復才計，不以 HTTP 先呈現取代 WS 恢復。後續全體計時核對另列，不將它的等待時間算進較早已完整恢復的分頁。恢復後核對全部提交原紀錄、身分原建立／到期時間與序號不倒退，另量計時器。
- 計時器：在頁內同一回呼中讀取 `data-elapsed-ms` 與 `performance.now()`，對齊伺服器牆鐘／單調基準。避免以 CDP 指令送出至回覆的整段排隊時間代替實際讀取時刻。早期方法不確定度過大而未通過的紀錄仍保留。

每筆同步延遲加不確定度不得超過 1,000ms；每筆計時差加不確定度不得超過 1,000ms；每筆恢復時間加不確定度不得超過 5,000ms。報所有未通過樣本及最壞上界，不以平均取代。完整程序遇未達標或觀測失效即保存並停止，未執行的輪次不能算通過。

## 背景、暫停與環境

使用原生 Chrome、CDP `noDefaults`，不使用 Playwright 的強制可見預設作背景效能證據。原始設定檔及測試產物在臨時目錄；不關閉使用者既有 Chrome、不更改省電、背景節流或休眠設定。記錄 CPU、記憶體、macOS、瀏覽器來源／版本、電源設定、實際 visibility、丟棄狀態與生命週期。

依 D39，只有真正 freeze／discard／OS sleep 才另列暫停；hidden 不等於凍結。暫停事件與全部觀察仍保留，恢復依原身分規則，不能延長 12 小時或復活撤銷／舊活動。受控 CDP 凍結及固定到期另有 Chrome 測試；未強制使用者電腦休眠，未把普通逾時排除。

## 保存與重跑

`docs/evidence/performance-acceptance.json` 指向最新一輪程序摘要；`docs/evidence/performance/<執行編號>.json` 保留每次嘗試，gzip JSONL 保留逐筆量測。新版本另保存 React 完整時間線與校準資料。資料沒有答案原文、密碼、token 或分頁第二憑證。失敗、無效、人工停止及清理錯誤應如實保留，不用新的成功檔覆蓋舊的失敗證據。

`probe:performance-preflight` 僅為 F3 單輪開始同步的工具預檢；`probe:acceptance42` 為真 Google 完整功能驗收，兩者都不能代替完整固定時限程序。最新完成狀態與限制見 [整合驗收報告](integration-acceptance.md)。


## D40 與版本固定

D40 已由使用者明確確認，門檻仍是 DOM 同步／計時 1 秒，授權 WS 與正確畫面皆恢復 5 秒。每筆另存 WS_revision、T_ws_arrival、T_ws_apply，不把較晚 WS 時刻回填成較早 DOM 的來源；未確認如實記錄。保留舊觀測器的全部資料及歸因更正。

正式程序記錄全部 src、migration、前端建置、工具、測試資料與設定指紋，結束核對版本未變。每輪有同名組員及接近 200 字的多行／emoji 答案；開始時另外核對學生全部作答欄位數。每輪入組前驗證 40 學生實際 hidden，前置不成立不能當作背景驗收。`CRS_PERF_DIAGNOSTIC=join`／`submit`／`reload` 僅診斷，不算完整 60 輪。
