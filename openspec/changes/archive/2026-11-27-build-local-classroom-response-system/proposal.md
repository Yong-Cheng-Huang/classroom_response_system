# Proposal

## Why

目前專案僅有 `docs/requirements.md` 與 OpenSpec 設定，尚無系統程式碼或既有能力規格。此變更將 Google Sheets Guided Notes 課堂活動轉為本機多分頁、以組別為單位的即時搶答系統，並把原始需求、Explore 的 29 項補充決策及本次確認的技術架構與匯出操作前提轉成可驗收契約。

## What Changes

- 建立老師密碼登入與學生免密碼選組；分頁身分獨立，支援固定 12 小時期限、30 秒斷線寬限及重啟恢復。
- 建立尚未匯入、待開始、搶答進行中、已結束四階段；僅待開始允許加入、離組及換組；成功重新匯入才替換活動並清除舊資料。
- 依已提供的兩份固定結構範本解析單題、題組及混合內容，支援工作表選取、既有答案與 2～20 組。
- 提供老師單題預覽、開始／確認結束、伺服器時間計時、全部組別結果與名次；提供學生暱稱、組員、分頁草稿及完整題組提交。
- 由伺服器統一排列提交與結束操作，交易式接受每組每題第一筆有效提交，保證單一第一名及重送一致性；不判斷答案正確性、不提供老師批改。
- 即時推送活動、成員與本組提交；學生結束前不可取得他組資料，結束後僅公開成功組答案及本組結果。
- 由老師 Google 帳號授權讀寫原始工作表，提供三種可重複及切換的匯出模式、全題定位驗證、人工變更保護與必要排版還原。
- 持久化題目、作答、名次、活動時間與身分；新活動不封存歷史，只例外保留最少文件輸出管理資訊。
- 以 macOS／Chrome 與2老師＋40學生的既有功能及量測證據驗收；依D41，本階段採紀錄型驗收。原同步／計時1秒、恢復5秒與完整60輪保留為後續改善目標，不宣稱目前全面達標。
- 依人工審查 R01～R06 補強分頁交接及恢復狀態、接收序號跨重啟延續、任務依賴與固定負載量測；分頁隔離列為早期技術關卡，不將候選機制宣稱為已驗證。
- 匯出結果待確認時允許老師再次確認放棄核對，成功匯入新場次後清除舊活動；原表可能已改動、不自動回滾，另保留最少未核實範圍資訊，後續不得自動覆蓋或清除。

- G2 邊界探針後使用者確認 D38／U01：無法精確判斷截止前後的非正常中斷，依最後已提交 CONNECTED／GRACE 狀態為原分頁重新提供 30 秒；已撤銷、已到固定期限及舊活動身分不恢復。此為明確例外政策，可能讓剛逾期但撤銷未落盤者恢復，不宣稱已證明歷史上未逾期。

- 第 13 階段使用者確認 D39：真正 Chrome 凍結／丟棄或 macOS 休眠另列暫停情境；一般背景保留原1／5秒比較基準（當前驗收依D41），恢復依既有身分規則，不新增期限例外或刪除失敗樣本。

- 第 13 階段使用者確認 D40：T_apply 取有權分頁首次正確 React DOM 呈現，另列 WS revision、到達與套用時刻；1／5秒保留為目標（當前驗收依D41），恢復觀測仍須授權WS快照與正確畫面皆恢復。

- 2026-11-27 使用者明確確認 D41：採紀錄型驗收，以既有量測、功能測試及缺失紀錄齊備作為本階段完成條件；同步／計時1秒、恢復5秒與F1～F3各20輪（共60輪）改列後續改善目標，不再阻擋13.3完成及本Change歸檔。不得把此決策寫成舊效能目標已通過；全部原始失敗與未執行輪次保留。分頁授權、30秒寬限、固定12小時、排名原子性及資料完整性均不放寬。

### 需求範圍與預期成果

涵蓋原需求 §1～§7 的全部功能及限制，並交付可追溯至規格情境、設計與任務的計畫。此次只修訂規劃文件，不代表功能已實作或已通過系統驗收。原決策 D01～D31 保留，已確認的審查修訂另記 D32～D37；具體工程程序與尚待驗證／確認的邊界分開記於 `design.md`。

### 不包含的功能

- 答案正確性判斷、老師批改、依答對與否計分。
- 歷史活動封存與查詢、已結束活動重新開啟、作答後修改答案。
- 任意版型的學習單辨識、同組草稿共同編輯、雲端部署及跨裝置使用驗收。
- 多個老師帳號、網頁改密碼與忘記密碼功能；Safari、Firefox 等其他瀏覽器的正式相容性驗收。
- 本次變更規劃階段不建立應用程式、資料庫實作或 Google Cloud 資源，不執行 Apply。

以上範圍不以 40 個學生作為產品上限，也不將範例題數或兩個子題當作功能上限。

## Capabilities

### New Capabilities

- `identity-access`：老師密碼、獨立分頁身分、學生暱稱、期限與角色授權。
- `activity-lifecycle`：四階段、確認操作、新活動替換、時間與舊資料清除。
- `guided-notes-import`：範本解析、工作表選擇、完整驗證、原始內容定位。
- `teacher-console`：老師預覽、活動控制、提交監看與完整結果。
- `student-participation`：選組、組員、題目揭露、草稿及學生操作限制。
- `realtime-recovery`：分流同步、連線寬限、身分恢復、重啟與效能驗收。
- `submission-ranking`：有效提交、題組原子性、順序、競爭與冪等重送。
- `activity-results`：成功答案、本組成績、題數與結果資料公開例外。
- `guided-notes-export`：三模式、I:K 欄、格內附註、來源檢查及一致匯出。
- `persistence-security`：必要資料持久化、共用 Google 授權、文字安全及錯誤處理。

### Modified Capabilities

無。專案目前沒有既有能力規格，因此全部使用 `ADDED Requirements`；不虛構 MODIFIED 或 REMOVED 項目。

## Impact

- 後續實作將新增本機前端、權威後端、持久化層、即時通訊、Google Sheets 與 OAuth 整合及測試；目前不存在可沿用的系統程式碼。
- 原始 `docs/requirements.md` 保持原樣，對話補充及例外明確記於本變更，不默默覆寫原需求。
- 本次 Propose 對話已額外確認採用 TypeScript、React 前端、Node.js 後端、SQLite、HTTP 命令與 WebSocket 推送，以及單一權威後端程序；不得於 Apply 擅自更換。具體套件與版本屬後續環境鎖定事項。
- Google OAuth、Sheets 讀寫、憑證本機保護及瀏覽器分頁恢復需要後續整合驗證；現有兩份範例的可讀權限不代表可寫權限。
